深入理解 JavaScript 事件循环

Windy

5 min read

JavaScript 是单线程语言，却能在浏览器中同时处理用户交互、网络请求和定时器。秘密就在于事件循环（Event Loop）——它协调调用栈、任务队列和微任务队列，决定代码何时执行。

调用栈与异步任务

同步代码按顺序压入调用栈执行。遇到 setTimeout、fetch、Promise 等异步 API 时，回调不会立刻执行，而是被注册到对应的队列中，等待调用栈清空后再处理。

CODE 
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

console.log('4');
// 输出: 1 → 4 → 3 → 2

为什么 3 先于 2？因为 Promise 回调属于微任务（Microtask），而 setTimeout 属于宏任务（Macrotask）。每一轮事件循环中，微任务会在下一个宏任务之前全部执行完毕。

事件循环的一轮

  1. 执行当前宏任务（如 script、setTimeout 回调）
  2. 调用栈清空后，执行所有微任务（Promise.then、queueMicrotask）
  3. 必要时渲染 UI（requestAnimationFrame 在此阶段）
  4. 取下一个宏任务，重复

async/await 的本质

await 之后的代码会被编译成 Promise 的 .then 回调，因此属于微任务。理解这一点能解释很多「明明 await 了，顺序却不对」的 bug。

CODE 
async function demo() {
  console.log('A');
  await Promise.resolve();
  console.log('B');
}
demo();
console.log('C');
// A → C → B

实践建议

  • 避免在微任务中执行耗时操作，会阻塞渲染
  • 大量 DOM 更新可分批用 requestAnimationFrame 或 setTimeout(0)
  • 调试时打开 Chrome Performance 面板，观察 Task 与 Microtask 时序
事件循环不是抽象概念，而是理解 JavaScript 并发模型的钥匙。掌握它，async 代码就不再是黑盒。
