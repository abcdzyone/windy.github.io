TypeScript 泛型：从入门到实践

Windy

6 min read

泛型让类型像参数一样传递，在保持类型安全的同时避免重复定义。它是 TypeScript 从「能写类型」到「会设计类型」的分水岭。

基础：类型参数

CODE 
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]);     // number | undefined
const s = first(['a', 'b']);    // string | undefined

编译器根据实参推断 T，一处定义，多种类型复用。

约束：extends

并非所有类型都有 .length。用 extends 限定上界：

CODE 
function logLength<T extends { length: number }>(val: T): void {
  console.log(val.length);
}

logLength('hello');   // OK
logLength(42);        // Error

工具类型的思路

内置的 Partial<T>、Pick<T, K>、Omit<T, K> 都是泛型 + 映射类型的组合。理解 keyof 和条件类型后，你可以自己写：

CODE 
type Optional<T, K extends keyof T> = Omit<T, K> & Partial<Pick<T, K>>;

interface User { id: number; name: string; email: string; }
type UserPatch = Optional<User, 'email'>;

实战：API 响应包装

CODE 
interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
}

async function fetchUser(id: string): Promise<ApiResponse<User>> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

前后端约定统一响应结构，泛型让 data 的类型随接口变化，IDE 自动补全不会丢。

常见误区

  • 过度泛型化：简单函数不必强行加 <T>
  • 滥用 any 作为泛型默认值，会吞掉类型检查
  • 复杂条件类型可读性差，适当拆成 type alias
